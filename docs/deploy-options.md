# デプロイ先の選択肢（AWS）

AWS にデプロイするときの構成の候補を比べる。**まだ決めていない。講義を確認してから決める。**
解説は [notes/08-aws-terraform-guide.md](../notes/08-aws-terraform-guide.md)。

> 費用は、**おおまかな目安**。為替、リージョン、使い方で変わる。決める前に、AWS の料金表と、料金計算ツールで確かめる。

## 1. このアプリを置くときの条件
| 部分 | 中身 | 置くときの要点 |
|---|---|---|
| 画面 | Vite でビルドした静的ファイル（HTML・JS・CSS） | 静的ファイルの置き場があればよい |
| サーバー | Spring Boot（Java 25）、8080番 | JVM が動く場所が要る。メモリは余裕が欲しい |
| データベース | PostgreSQL 18 | 永続化が必要。Flyway が起動時にテーブルを作る |
| 通信 | 画面から `/api` に送る（開発中は Vite のプロキシで中継） | 本番では、同じ入口で `/api` をサーバーに振り分けるか、CORS を設定する |
| 設定 | DB の接続先・パスワードは環境変数（`POSTGRES_*`） | パスワードは秘密にする |

## 2. 構成の候補

### A：S3 ＋ CloudFront ＋ EC2 1台（DB も同居）
- 画面：S3 に置き、CloudFront で配信
- サーバー：EC2 1台で、Docker（バックエンドと PostgreSQL）を動かす
- 費用の目安：月に数ドル〜十数ドル（無料枠の対象かは、アカウントの状況で変わる）
- 長所：安い。仕組みが目に見えやすく、学習向き
- 短所：EC2 を自分で管理する（OS の更新など）。DB のバックアップを自分で用意する。1台が止まると全部止まる

### B：S3 ＋ CloudFront ＋ ECS Fargate ＋ RDS ＋ ALB
- 画面：S3 ＋ CloudFront
- サーバー：ECS Fargate（コンテナを、サーバー管理なしで動かす）。入口は ALB
- データベース：RDS（PostgreSQL）
- 費用の目安：月に **20ドル以上**。ALB と RDS は、使っていなくても課金される
- 長所：実務に近い。DB の自動バックアップ、サーバーの管理が少ない
- 短所：高い。部品が多く、Terraform の量も増える

### C：その他（必要なら検討）
- AWS App Runner など、コンテナを手軽に動かすサービス
- 画面もサーバーも EC2 1台に載せる（CloudFront なし）。最も単純だが、HTTPS が手間

## 3. 比べる表
| | A：EC2 同居 | B：Fargate ＋ RDS |
|---|---|---|
| 月額の目安 | 低い | 高い |
| 学習できる範囲 | 狭くて深い（Linux、Docker） | 広い（コンテナ、マネージド DB、ALB） |
| Terraform の量 | 少なめ | 多め |
| 運用の手間 | 自分で更新・バックアップ | AWS 任せの部分が多い |
| 壊れたときの影響 | 全部止まる | 部分的 |
| 消すとき（`destroy`） | 簡単 | 簡単だが、RDS は削除前のバックアップ設定に注意 |

## 5. 公開のセキュリティ（最重要）
現状のアプリは、ログインなしで、`/api/backup` が**全データの書き出し・入れ替え**を受け付ける（[非機能要件](non-functional-requirements.md) の5章は「外部に公開しない」前提）。
インターネットに出す前に、次のいずれかが必要。

| 案 | 内容 | 手間 | 注意 |
|---|---|---|---|
| ① 自分のIPからだけ許可 | セキュリティグループ等で、自宅のIPだけ通す | 小 | IPが変わると、つながらなくなる。固定IPでないと不便 |
| ② ログインを足す | アプリに認証（Spring Security など）を追加 | 大 | 仕様の変更。画面とAPIの両方に手が入る |
| ③ 手前に認証をつける | CloudFront／ALB の前で認証する（例：Cognito） | 中 | AWS の部品が増える |
| ④ 公開しない | VPN 等で、自分だけがつなぐ | 中 | そもそもの目的（公開）とは違う |

どれにするかは、**ユーザーが決める**（仕様に関わるため）。決まるまで、Terraform で「誰でもつなげる」状態を作らない。
