# 01 Git と GitHub

## 1. 全体の流れ（1周）
機能を1つ作る、文書を1つ直す、といった「1つの目的」ごとに、次の流れを繰り返す。

```
git switch main                      mainに移動する
git pull                             GitHubの最新を取り込む
git switch -c ブランチ名             新しいブランチを作って移動する
（ファイルを修正して保存）
git status                           変更されたファイルを確認する
git diff                             何が変わったか確認する
git add ファイル名                   コミットに入れるファイルを選ぶ
git commit -m "メッセージ"           変更を記録する
git push -u origin ブランチ名        GitHubに送る（そのブランチで初回のみ）
→ GitHubで Pull Request（PR）を作る → 内容を確認 → Merge
git switch main                      mainに戻る
git pull                             マージした内容を、手元に取り込む
git branch -d ブランチ名             使い終わったブランチを消す
git fetch --prune                    GitHubで消えたブランチの記録を、手元から消す
```

## 2. コマンド一覧

| コマンド | 意味 | ポイント |
|---|---|---|
| `git status` | 今の状況を見る | 迷ったら、まずこれ。今のブランチ、変更したファイルが分かる |
| `git switch ブランチ名` | 別のブランチに移動する | |
| `git switch -c ブランチ名` | 新しいブランチを作って移動する | `-c` は create（作る）。**必ず main を最新にしてから作る** |
| `git pull` | GitHubの最新を、手元に取り込む | マージのあとは、必ず実行する |
| `git diff` | 変更の内容を見る | 赤い行＝消えた、緑の行＝追加された。`q` で閲覧モードを終わる |
| `git add ファイル名` | コミットに入れるファイルを選ぶ（ステージング） | `.claude/` など、入れたくないものは、指定しない |
| `git commit -m "メッセージ"` | 変更を記録する | **`-m` を忘れない**。忘れるとエディタ（vim）が開く |
| `git push -u origin ブランチ名` | GitHubに送る | `-u` は「手元とGitHubのブランチを紐づける」。初回のみ。2回目からは `git push` |
| `git branch -d ブランチ名` | マージ済みのブランチを消す | 未マージだと警告が出る（安全）。`-D`（大文字）は強制削除なので、初心者は使わない |
| `git branch -a` | ブランチの一覧（手元とGitHub側の記録） | 今いるブランチに `*` が付く |
| `git fetch --prune` | GitHubで消えたブランチの記録を、手元から消す | 赤字の `remotes/origin/...` を整理する |
| `git stash` / `git stash pop` | 変更を一時的にしまう／戻す | 間違ったブランチで編集してしまったときに使う |
| `git log --oneline` | コミットの履歴を、1行ずつ見る | `q` で戻る |

## 3. GitHub CLI（gh コマンド）

| コマンド | 意味 |
|---|---|
| `gh auth login` | GitHubにログインする（初回のみ。ブラウザで承認する） |
| `gh auth status` | ログインしているか確認する |
| `gh pr create` | PRを作る（Claude Codeが、代わりに実行してくれる） |

## 4. 用語

| 用語 | 意味 |
|---|---|
| リポジトリ | プロジェクトのファイルと、変更の履歴を、まとめて保存する場所 |
| ブランチ | 本線（main）から、枝分かれした作業用の場所。本線を壊さずに、作業できる |
| コミット | 変更を、メッセージ付きで、記録すること |
| プッシュ | 手元の記録を、GitHubに送ること |
| プル | GitHubの最新を、手元に取り込むこと |
| PR（Pull Request） | 「この変更を、mainに取り込んでください」という依頼 |
| マージ | 作業用ブランチの内容を、mainに取り込むこと |
| origin | GitHub上のリポジトリの、標準的な呼び名 |
| ステージング | コミットに入れるファイルを、選ぶこと（`git add`） |

## 5. コミットメッセージのマナー
- **1行目は、短く**（目安：30〜50文字）
- **何をしたか分かる**ように書く（✕「修正」→ ○「READMEの誤字を修正」）
- **1コミット＝1つの目的**
- 迷ったら、「このコミットを取り込むと、プロジェクトは＿＿＿」という文を、頭の中で完成させる

## 6. つまずきやすい点

| 症状 | 原因と対処 |
|---|---|
| 画面が `(END)` で止まった | 閲覧モード（ページャー）。`q` を押すと戻る |
| 日本語入力のまま、コマンドを打った（「ｇｉｔ」など） | `半角/全角` キーで、英字入力に切り替える |
| コマンドが、Claudeのチャット欄に入っていた | コマンドは、**下のTerminal**に入力する |
| 新しいブランチで `git push` したら、エラーになった | 初回は `git push -u origin ブランチ名` |
| 間違えて、`main` の上で編集を始めた | 慌てず、`git switch -c 新しいブランチ名` で、変更ごと、移動できる（コミット前なら） |
| `git branch -d` で「not fully merged」と出た | まだマージされていない。**そのままにして**、状況を確認する |

## 7. マージのあとの整理（セット）
GitHubでマージしても、**手元のmainは、自動では更新されない。**

```
git switch main
git pull
git branch -d 使い終わったブランチ名
git fetch --prune
```

## 8. マージ前のPRに、修正を追加する
PRを作ったあとで、直したい点に気づいたとき（今回は、画像の説明文の間違いに気づいた）。**新しくPRを作り直す必要はない。**

```
（同じブランチで、ファイルを直して保存）
git add ファイル名
git commit -m "修正の内容"
git push                  ← 2回目以降なので、-u は不要
```
**同じブランチにプッシュすると、作成済みのPRに、自動で追加される。** PRの「Commits」タブで、コミットが増えたことを確認できる。

| 状況 | 対応 |
|---|---|
| PRが、まだマージされていない（OPEN） | 同じブランチに、追加コミットをプッシュする |
| PRが、すでにマージされた | 新しいブランチを作り、新しいPRにする |

PRの状態は、`gh pr view 番号 --json state` で確認できる（`OPEN` か `MERGED` か）。

## 9. 作業を始める前の確認（習慣）
- **今のブランチを確認する**（`git branch --show-current`）。`main` の上で、編集を始めない
- 間違えて `main` の上で編集を始めても、**コミット前**なら、`git switch -c 新しいブランチ名` で、変更ごと移動できる
- コミットするファイルは、**`git add` で、1つずつ指定する**（`.claude/` など、入れたくないものを避ける）
- コミットする前に、**`git status` で、対象のファイルを確認する**

## 10. やってみよう
1. `git status` を打って、今のブランチと、変更のあるファイルを確認する
2. `git log --oneline` で、今までのコミットの履歴を見る（`q` で戻る）
3. `git branch -a` で、ブランチの一覧を見る
