# 03 プロトタイプの仕組み

`prototype/` の中の、3ファイルで動いている。**使い捨ての試作**で、本番（Spring Boot + React）の土台にはしない。

## 1. 動かし方
`prototype/index.html` を、Chromeで開く（ダブルクリック）。インストールは不要。

## 2. 3つのファイルの役割

| ファイル | 役割 | たとえ |
|---|---|---|
| `index.html` | 構造（何が、どこにあるか） | 家の骨組み |
| `style.css` | 見た目（色、大きさ、配置、影） | 壁紙や内装 |
| `app.js` | 動き（クリックしたら、どうなるか） | 電気や水道 |

## 3. app.js の構造
上から順に、次のようにできている。

| 部分 | 役割 |
|---|---|
| ヘルパー | 日付の計算（`ymd`、`fmtDue`、`isOverdue`）、文字の安全な表示（`esc`） |
| アイコン | 線画のSVGを、文字列として持っている（`ICONS`） |
| データ | `state`：列とカードの、本体のデータ。`ui`：画面の一時的な状態（追加中、編集中、ドラッグ中） |
| 保存・読み込み | `localStorage`（ブラウザの中）に保存する（`save` / `load`） |
| 描画 | `render()`：`state` をもとに、画面を作り直す（`cardHtml`、`draftHtml`） |
| ポップオーバー | 色見本、カレンダーの小さな窓（`openPalette`、`openCalendar`、`placePop`） |
| 操作 | 追加の確定、編集の確定、移動、期限順（`commitDraft`、`commitEdit`、`moveCard`、`sortByDue`） |
| イベント | クリック、キー入力、ドラッグ＆ドロップへの反応 |
| バックアップ | ファイルに保存、ファイルから読み込み |

### 基本の考え方：「データを変える → 画面を作り直す」
```
操作（クリックなど）
   ↓
state（データ）を変える
   ↓
save()  で保存する
   ↓
render() で、画面を作り直す
```
画面を直接いじるのではなく、**データを変えて、画面は、そこから作り直す**。この形は、本番のReactでも、同じ考え方。

### データの形
```
state = {
  cols: [
    { id: 'todo',  name: 'ToDo',  cards: [ { id, title, color, due }, ... ] },
    { id: 'doing', name: '作業中', cards: [ ... ] },
    { id: 'done',  name: '完了',   cards: [ ... ] }
  ]
}
```
`cards` の**並び順が、そのまま、画面の上からの順番**になる。並び順の保存は、この配列の順番を保存すること。

## 4. 主な仕組み

### イベントの委任（data-action）
ボタンには、`data-action="add"` のような**目印**を付けている。カードは、画面を作り直すたびに、入れ替わるので、**ボード全体（board）で、まとめて、クリックを受け取り**、目印を見て、何をするかを決める。

### ドラッグ＆ドロップ
ブラウザの標準機能を使う。

| イベント | 起きるとき | やっていること |
|---|---|---|
| `dragstart` | カードをつかんだ | どのカードを動かしているか覚える |
| `dragover` | カードを運んでいる最中 | マウスの高さから、「何番目に入るか」を計算し、青い線を出す |
| `drop` | マウスを離した | カードを、その位置に移して、保存し、画面を作り直す |
| `dragend` | ドラッグが終わった | 青い線を消す |

### 入力欄の外のクリック
クリックの「最初」（capture）に、「入力欄の外か」を調べて、外なら確定する。こうすると、**押した先のボタンも、そのまま働く**（1回のクリックで済む）。

### 日本語入力のEnter
日本語の変換中のEnterは、「確定」に使わない（`e.isComposing`）。使うと、変換の確定で、カードが追加されてしまう。

### バックアップ
- 保存：データをJSON（文字のデータ）に変えて、ファイルとしてダウンロードさせる（`Blob`）
- 読み込み：選んだファイルを読み（`FileReader`）、正しい形か確認（`validState`）し、確認メッセージのあとで、置き換える

### 自作のカレンダー
Chromeの標準カレンダーは、位置をプログラムで決められない。そのため、月のカレンダーを自作した（6週間分＝42個の日付）。位置は、アイコンのすぐ下。下に入らないときは、上に出す。

## 5. style.css のポイント

| 機能 | 使っているCSS |
|---|---|
| 色の一括管理 | `:root { --c-red: ...; }`（CSS変数）。色を直すときは、ここだけ |
| 列の幅の固定 | `flex: 0 0 320px` |
| カードの影 | `box-shadow`（近くの影と、遠くの影を、重ねる） |
| マウスを乗せたとき、浮き上がる | `:hover` と `transform: translateY(-2px)`、`transition`（なめらかに変える） |
| アイコンの表示 | マウスを乗せたときだけ `opacity: 1` |
| 線画のアイコン | SVGの `stroke: currentColor`（文字の色に合わせる） |

## 6. 自動テスト（私が、画面を出さずに確認していたこと）

### 何をしていたか
Claude Codeが、プロトタイプを作ったあと、**人が操作する代わりに、プログラムで操作を再現**して、動作を確認した。

```
① プロトタイプのファイルを、作業用の一時フォルダにコピーする
② テスト用のプログラム（test.js）を、一緒に読み込ませる
③ 画面を表示しない Chrome（ヘッドレスChrome）で、ページを開く
④ test.js が、ボタンのクリックや、キー入力を、自動で再現し、結果を書き出す
⑤ 結果を読んで、合格（OK）か不合格（NG）かを見る
```
確認した項目は、追加、編集、削除、色、期限、期限順、ドラッグ＆ドロップ、期限切れの赤文字など、約60個。

### `$scratch` とは
コマンドの中に、`$scratch = "C:\Users\...\scratchpad\protocheck"` という行が出てきた。

| 部分 | 意味 |
|---|---|
| `$` | PowerShellで、**変数**（値に付ける名前）を表す印 |
| `scratch` | 変数の名前。「作業用」という意味の英語（scratch）から付けた |
| `= "C:\Users\..."` | その名前に、**作業用の一時フォルダの場所**を入れている |

あとで、`"$scratch\test.html"` のように使うと、長い場所を、毎回書かずに済む。**同じ値を何度も使うときの、省略の仕組み**。

### 後から変えたこと：ブラウザを遠隔操作して、実際の時間でテストする
最初のテストは、「画面を出さずに、ページを開いて、結果を読む」方式だった。この方式には、**仮想の時計**が使われる（待ち時間を、早送りする仕組み）。

画像の保存や縮小は、**ブラウザの内部の別の処理**（IndexedDB、画像の読み込み）で行われる。仮想の時計は、これらの終わりを待たずに、**先に進んでしまい**、「時間切れ」になった。アプリの不具合ではなく、**テストの方法の問題**だった。

そこで、次の方式に変えた。

```
① Chrome を、画面なしで起動し、「遠隔操作を受け付ける口」（ポート）を開ける
② PowerShell から、その口に接続して、「このページを開いて」「結果を教えて」と、命令を送る
③ 結果が出るまで、実際の時間で待つ
④ 結果を読んで、合格（OK）か不合格（NG）かを見る
```
この遠隔操作の仕組みを、**CDP（Chrome DevTools Protocol）**と呼ぶ。Chromeの開発者ツール（`F12`）も、同じ仕組みで動いている。

**学んだこと**：テストが失敗したとき、**アプリが悪いのか、テストが悪いのか**を、切り分ける。エラーが出ていないのに失敗するときは、テストの待ち方を疑う。

### 自動テストで確認できないこと
- 実際のマウスでの、操作の**手触り**
- 見た目の**好み**（色、大きさ）
- ファイルを選ぶ操作（バックアップの読み込み）

これらは、人が動かして確認する。

## 7. 背景の機能
画面の右上の「背景」ボタンから、背景を選べる。

| 選択肢 | 内容 |
|---|---|
| 無地 | 今までの、ほぼ白の背景 |
| 青空・夕焼け・星空 | 標準の画像（ChatGPTで作成）で表示する |
| 自動（時間帯） | 5〜16時は青空、16〜18時は夕焼け、18時〜翌5時は星空 |

### 仕組み
```
背景を選ぶ
   ↓
state.settings.background に、選んだ名前を入れる（'sky' など）
   ↓
save() で保存する
   ↓
applyBackground() が、<body> に、クラス名（bg-sky など）を付ける
   ↓
CSSが、そのクラス名に合わせて、背景を表示する
```
**見た目は、CSSが決める。** JavaScriptは、クラス名を付け替えるだけ。

### 「自動」の時間帯を決める部分
```js
function bgForNow() {
  var h = new Date().getHours();        // 今の「時」（0〜23）
  if (h >= 5 && h < 16) return 'sky';
  if (h >= 16 && h < 18) return 'sunset';
  return 'night';
}
```
画面を開いたままでも変わるように、**30秒ごとに**確認している（`setInterval`）。

### 見た目の工夫（style.css）

| 工夫 | 内容 |
|---|---|
| 画像の下に、グラデーションを残す | 画像が読み込めないときの**保険**（フォールバック）。画像の層が、一番上、グラデーションが、その下 |
| 画像を画面いっぱいに広げる | `center / cover`。縦横の比が違っても、はみ出た部分を切り取って、全面を覆う |
| 背景を画面に固定する | `background-attachment: fixed`。スクロールしても、背景は動かない |
| 列を少し透けさせる | `rgba(…, 0.75)`（75%の濃さ）と、`backdrop-filter: blur`（背景をぼかす） |
| 星空のときは、列を暗くする | 明るい列だと、暗い背景の上で、灰色っぽく見えるため。見出しは、明るい文字にする |
| カードは、不透明のまま | どんな背景でも、文字が読めるようにするため |

## 8. 自分の画像を、背景にする
青空・夕焼け・星空に、**自分のPCの画像**を割り当てられる。

### 流れ
```
「画像を選ぶ」を押す → ファイルを選ぶ
   ↓
種類（JPEG・PNG・WebP）と大きさ（20MBまで）を確認する
   ↓
canvas（絵を描く場所）に描いて、横1920pxに縮小する（小さい画像は、拡大しない）
   ↓
JPEGにして、ブラウザの中（IndexedDB）に保存する
   ↓
表示用のURL（blob:...）を作り、CSSの変数 --bg-image に入れる
   ↓
<body> に has-img のクラスが付き、画像が、暗幕（黒20%）つきで表示される
```

### localStorage と IndexedDB の違い

| | localStorage | IndexedDB |
|---|---|---|
| 入れられる量 | 約5MBまで | もっと大きい |
| 入れられるもの | 文字（JSON） | 文字のほか、画像などのファイル（Blob） |
| 今回の使い道 | カードや設定 | 自分の背景画像 |

**Blob**（ブロブ）は、画像などの、まとまったデータの塊のこと。

### 決めごと（要件から）
- 画像は、**ブラウザの中にだけ**保存する。外部に送らず、GitHubにも上がらない
- **バックアップには、含めない**。バックアップを読み込んでも、登録済みの画像は、そのまま残る
- 「元に戻す」で、登録した画像を消し、標準の画像に戻す

### 開発中に見つけた不具合
「画像を選ぶ」を押すと、ファイル選択のために、プログラムが**画面に見えない入力部品を、クリックする操作**を行う。これが、「**窓の外をクリックした**」と誤って判断され、選択の窓が、閉じてしまった。**クリックされた部品を調べて、除外する**ことで直した。

## 9. 本番（Spring Boot + React）との関係

| プロトタイプ | 本番 |
|---|---|
| データは、ブラウザの中（localStorage） | データベースに保存（サーバー経由） |
| `render()` で、画面を作り直す | Reactが、データの変化に応じて、画面を更新する |
| 日付の部品、アイコンは、自作 | 部品集（ライブラリ）を使うことが多い |

**画面の構成、動き、色、決まったルール**は、そのまま、本番の見本になる。

## 10. やってみよう
1. `prototype/index.html` を開き、カードを追加・移動・削除してみる
2. ブラウザの開発者ツール（`F12`）を開き、「Application」→「Local Storage」で、保存されているデータを見る
3. `style.css` の `--c-red` の色を、少し変えて、再読み込みしてみる（色が変わる）
4. `app.js` の `fmtDue` を読んで、「期限 ○月○日」が、どう作られているか見る
