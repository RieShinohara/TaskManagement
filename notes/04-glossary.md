## Web の技術

| 用語 | 意味 |
|---|---|
| HTML | 画面の構造を書く言語 |
| CSS | 画面の見た目を書く言語 |
| JavaScript | 画面の動きを書く言語 |
| DOM | ブラウザが、HTMLを、プログラムから触れる形にしたもの |
| イベント | クリックや、キー入力など、ユーザーの操作 |
| localStorage | ブラウザの中に、データを保存する仕組み |
| JSON | データを、文字で表す形式。APIのやり取りと、バックアップのファイルに使っている |
| SVG | 線や図形で描く画像の形式。拡大しても、きれい |
| Mermaid | 文字を書くだけで、図（ER図など）になる書き方 |
| ポップオーバー | クリックした場所の近くに、小さく出る窓 |
| モーダル | 画面の上に出て、閉じるまで、ほかの操作ができない窓 |
| プロトタイプ | 動きや見た目を確かめるための、試作品 |

## 画像・ブラウザの仕組み

| 用語 | 意味 |
|---|---|
| IndexedDB | ブラウザの中に、大きなデータ（画像など）を保存する仕組み。localStorageより、たくさん入る |
| Blob | 画像などの、まとまったデータの塊 |
| canvas | JavaScriptで、絵を描いたり、画像を加工したりする場所（画像の縮小に使った） |
| グラデーション | 色が、なめらかに変わる塗り方（CSSで描く） |
| 暗幕 | 画像の上に重ねる、薄い黒。文字を読みやすくする |
| フォールバック | 本来の方法が使えないときの、代わりの方法（「保険」）。画像が読み込めないとき、グラデーションを表示する |
| キャッシュ | ブラウザが、読み込んだファイルを、一時的に覚えておくこと。古い画像が残って見えるときは、`Ctrl + F5` |
| 解像度 | 画像の細かさ（横×縦のピクセル数）。例：1920×1080 |
| 縦横の比（アスペクト比） | 画像の横と縦の比。16:9が、一般的な画面の比 |
| JPEG / PNG / WebP | 画像のファイル形式。写真には、JPEGやWebPが向いている |
| ライセンス | 素材などを、どう使ってよいかを定めた、利用の許可 |
| CDP（Chrome DevTools Protocol） | Chromeを、プログラムから遠隔操作するための仕組み。自動テストに使った |
| ポート | パソコンの中で、プログラム同士が、やり取りするための「口」 |

## 開発の考え方

| 用語 | 意味 |
|---|---|
| Single Source of Truth | 情報の置き場所を、1か所にすること |
| スコープクリープ | 作る範囲が、いつの間にか広がること |
| 使い捨ての試作 | 確認のために作り、本番には使わない作り方 |
| 自動テスト | 人の代わりに、プログラムで動作を確認すること |
| ヘッドレスブラウザ | 画面を表示せずに動く、ブラウザ |
| 変数 | 値に付ける名前（PowerShellでは、`$` から始まる） |

## バックエンド・DB
詳しくは `05-backend-guide.md` を参照。

| 用語 | 意味 |
|---|---|
| バックエンド | サーバー側のプログラム。画面からのお願いを受けて、DBを読み書きする |
| Java | プログラミング言語。バックエンドに使う |
| LTS | 長期サポート版。Java 25 は、現行の最新のLTS |
| Spring Boot | Javaで、サーバー側のプログラムを作るための道具（フレームワーク） |
| Gradle | Javaのプロジェクトの、ビルド（組み立て）と、部品の管理をする道具 |
| Gradle Wrapper（gradlew） | Gradleを、自動で用意して動かす仕組み。別にインストールしなくてよい |
| 雛型 | 最小限の、作り始めの形（Spring Boot の最初のプロジェクト） |
| API | プログラム同士が、やり取りするための窓口 |
| REST API | GET / POST / PUT / DELETE などの決まりに沿って作る、API |
| エンドポイント | APIの窓口の住所（例：`/api/cards`） |
| ステータスコード | APIの返事に付く番号（200 成功、400 お願いが変、404 見つからない、500 サーバーの問題） |
| DB（データベース） | データを、整理して保存する仕組み |
| PostgreSQL | データベースの種類（RDBMS）。今回使う |
| テーブル | DBの中の、表。列と行でできている |
| SQL | DBに出す命令の言葉（INSERT、SELECT、DELETE など） |
| 主キー（PK） | 表の1行を特定する番号（`id`） |
| 外部キー（FK） | 別の表の行を指す番号。`card.column_id` が `board_column.id` を指す |
| CRUD | Create（作る）、Read（読む）、Update（更新する）、Delete（消す）の4つの基本操作 |
| JPA | Javaのクラスで、DBのデータを扱う決まり |
| Hibernate | JPAを、実際に動かす部品 |
| Entity | テーブルに対応するJavaのクラス |
| Repository | DBの読み書きを担当する部品 |
| Service | 業務の処理を担当する部品 |
| Controller | APIの窓口を担当する部品 |
| DTO | APIでやりとりするデータの形 |
| ddl-auto | 起動のとき、Entityに合わせて、テーブルを自動で作る設定 |
| Flyway | テーブルの定義を、SQLファイルとして記録・管理する道具（将来の候補） |
| バリデーション | 入力が正しいかの検査（タイトルが空でないか、など）。入口（`@Valid`）で行い、通らなければ400にする |
| Docker | アプリを、コンテナ（隔離された入れ物）で動かす道具 |
| コンテナ | Dockerで動く、隔離された入れ物 |
| イメージ | コンテナの元になる、ひな形 |
| ボリューム | コンテナの外に、データを保存する場所。コンテナを消しても残る |
| docker compose | コンテナの設定を書いたファイルで、まとめて起動・停止する道具 |
| ヘルスチェック | サーバーやDBが、正常に動いているかを、自動で確かめる仕組み |
| .env | パスワードなどを書く、個人用の設定ファイル。コミットしない |
| Testcontainers | テストのときだけ、使い捨てのDBをDockerで起動する道具 |
| Connection refused | 接続を断られたこと。DBが動いていないときに出る |
| React | 画面を、部品（コンポーネント）の組み合わせで作るための道具（JavaScript） |
| TypeScript | JavaScriptに、型の検査を加えた言語。書き間違いを、実行前に見つけられる |
| Vite | Reactの画面を、開発するための道具。開発用サーバーとビルドを担う |
| Tailwind CSS | 見た目を、短い指定（`class="p-3"` など）で書くための道具 |
| npm | JavaScriptの部品を、入れたり、コマンドを実行したりする道具 |
| Node.js | JavaScriptを、ブラウザの外で動かす土台。npm や Vite が動くのに必要 |
| コンポーネント | 画面の部品（例：カード、列）。組み合わせて、画面を作る |
| フック（hook） | Reactで、状態の管理などをするための仕組み。名前は `use` で始まる（例：`useBoard`） |
| プロキシ | 代わりに取り次ぐこと。開発中は、Vite が `/api` をバックエンドに中継する |
| CORS | ブラウザが、別の場所（ポート違いも含む）へのお願いを、安全のために制限する仕組み |
| Vitest | 画面側の自動テストの道具 |

## 機能づくりで出てきた用語（バックエンド）
詳しくは `05-backend-guide.md` の12章以降を参照。

| 用語 | 意味 |
|---|---|
| トランザクション | 複数のDBの操作を、「全部成功するか、全部なかったことにするか」のどちらかにまとめる仕組み。バックアップの読み込みで使った（`@Transactional`） |
| 読み取り専用のトランザクション | 読むだけの処理に付ける指定（`readOnly = true`）。この中で書き込む（INSERT など）と、エラーになる |
| 204 No Content | 「成功した。でも、返す中身はない」という返事（削除のあとなど） |
| 連番の振り直し | 並び順を、0,1,2,… の番号に直すこと。サーバーが行うので、画面は数値を計算しなくてよい |
| 安定な並べ替え | 同じ値のものの順番を、変えない並べ替え。期限が同じカードの順番が、そのまま残る |
| bytea | PostgreSQLで、バイト列（画像など）を入れる型 |
| バイト列 | データを、数字（0〜255）の並びで表したもの。画像のファイルも、バイト列 |
| マジックナンバー | ファイルの先頭にある、種類を表す目印。JPEGは `FF D8 FF`。名前や `Content-Type` は偽れるので、中身で見分ける |
| ETag | 「このデータの版」を表す目印。ブラウザが「変わってない？」と聞いて、変わっていなければ、送り直さない（304） |
| 304 Not Modified | 「前と同じなので、送り直しません」という返事 |
| MockMvc | 実際にサーバーを起動せずに、APIを呼んで試す、Springのテストの道具 |
| モック | 本物の代わりに使う、偽物。通信（`fetch`）を偽物にして、画面をテストする |

## 機能づくりで出てきた用語（画面）
詳しくは `06-frontend-guide.md` の6章以降を参照。

| 用語 | 意味 |
|---|---|
| dnd-kit | ドラッグ＆ドロップを実現する部品（React用）。このアプリで使っている |
| センサー | dnd-kit で、「何を、つかむ操作とみなすか」を決める部品（マウス、キーボード） |
| 楽観的更新 | 保存の結果を待たずに、先に画面を変えること。失敗したら、元に戻す。ドラッグ＆ドロップと、背景の選択で使った |
| ポータル | 部品を、画面の別の場所（`body` の直下）に出す仕組み。カレンダーなどが、枠で切り取られないようにする |
| position: fixed | 画面に固定する指定。スクロールしても動かない（背景、小さな窓） |
| ただの関数（純粋関数） | 画面を使わず、入力だけで結果が決まる関数。単体テストしやすい（`lib/` のもの） |
| 単体テスト | 1つの関数だけを取り出して、確かめるテスト。境目の値（4:59 と 5:00 など）を調べる |
| jsdom | テスト用の、偽のブラウザ。画面上の位置や、canvas の描画は、動かない |
| HMR | ファイルを保存すると、開いている画面が、自動で更新される開発の仕組み（Vite） |
| リファクタリング | 動きを変えずに、中身を整理すること。例：小さな窓の位置決めを、共通の部品にした |
| git stash | 作業中の変更を、一時的にしまっておく Git の機能。ブランチを切り替えるときに使った |
| アクセシビリティ | 目の不自由な人や、キーボードだけの人も使えるようにすること。`aria-label`、フォーカス、キーボード操作など |

## 機能づくりで出てきた用語（仕様・進め方）

| 用語 | 意味 |
|---|---|
| 非機能要件 | 機能ではなく、速さ・使いやすさ・読みやすさなどの要件。「5色が見分けられること」など |
| 対象外 | 作らないと決めたもの。「将来追加する機能」（作るかもしれない）とは別 |
| 破壊的な操作 | 元に戻せない操作（削除、バックアップの読み込み）。実行前に確認を出す |
