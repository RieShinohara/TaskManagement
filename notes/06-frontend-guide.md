# 06 フロントエンド（画面）の仕組み

`frontend/` の中の、React + TypeScript の画面。**本番の画面**になる。
使い方は [frontend/README.md](../frontend/README.md)、技術の決定は [docs/tech-stack.md](../docs/tech-stack.md) を参照。

## 1. 道具の役割
| 道具 | 役割 | たとえ |
|---|---|---|
| Node.js | JavaScript を、ブラウザの外で動かす土台 | 厨房の電気・ガス |
| npm | 部品（ライブラリ）を入れたり、コマンドを実行したりする | 食材の仕入れ係 |
| Vite | 開発用のサーバーと、本番用のビルドをする | 試食用の仮設キッチン |
| React | 画面を「部品（コンポーネント）」の組み合わせで作る | 料理の型 |
| TypeScript | JavaScript に「型」を足す。書き間違いを、実行前に見つける | レシピの誤字チェック |
| Tailwind CSS | `class="p-3 rounded-lg"` のように、短い指定で見た目を決める | 盛り付けの定型 |
| Vitest | 画面の部品が、思ったとおりに動くか、自動で確かめる | 味見の自動化 |

- `package.json`：使う部品の一覧と、コマンド（`npm run dev` など）が書いてある
- `package-lock.json`：実際に入った部品の、正確なバージョンの記録（コミットする）
- `node_modules/`：入れた部品の置き場。大きいので、コミットしない（`npm install` でいつでも再現できる）

## 2. 画面が、データを表示するまでの流れ
```
ブラウザ → (5173番) Vite → /api/... は、そのまま (8080番) バックエンドへ中継 → DB
```
1. 画面を開くと、`App` が `useBoard` を呼ぶ
2. `useBoard` が、`/api/columns`（列）と `/api/cards`（カード）を、同時に取りにいく
3. 結果を、`Board` → `BoardColumn` → `CardItem` の順に渡して、表示する

### なぜ、プロキシ（中継）を使うのか
- 画面（5173番）から、別の場所（8080番）に直接お願いすると、ブラウザが、安全のために止める（**CORS**）
- Vite に「`/api` は、8080番に回して」と設定（`vite.config.ts` の `proxy`）すると、ブラウザには「同じ場所とのやりとり」に見える
- そのため、バックエンドに、CORS の設定を足さずに済む
- バックエンドが止まっているときは、プロキシが `502` を返す。画面では「サーバーに接続できません」と表示する

## 3. フォルダの構成（`frontend/src/`）
| 場所 | 役割 |
|---|---|
| `api/types.ts` | APIが返すデータの「型」（バックエンドの Response と同じ形） |
| `api/client.ts` | APIを呼ぶ関数。失敗したときの、分かりやすいエラーメッセージも作る |
| `hooks/useBoard.ts` | 列とカードを取得して、「読み込み中／エラー／成功」を管理する |
| `components/` | 画面の部品（SearchBar、Board、BoardColumn、CardItem） |
| `lib/date.ts` | 期限の表示（「期限 10月15日」）と、期限切れの判定 |

## 4. 学んだポイント
- **状態（state）**：画面が覚えている値。値が変わると、React が画面を描き直す
- **日付は、文字列のまま比べる**：`'2026-10-12' < '2026-10-15'` のように、同じ形（YYYY-MM-DD）なら、そのまま日付の順に比べられる。`Date` を使うと、時差でずれることがある
- **古い結果で上書きしない**：検索を続けて行うと、前の問い合わせの結果が、あとから届くことがある。`useBoard` は、条件ごとに結果を持ち、今の条件のものだけを使う
- **テストの片付け**：Vitest では、テストのあとに、描いた画面を自分で片付ける（`cleanup`）。忘れると、前のテストの画面が残って、「同じ要素が複数ある」と失敗する
- **Tailwind の指定がぶつかる**：`bg-white` と `bg-[#4f7cff]` を同時に付けると、どちらが勝つかは、CSSの並び順で決まる。ボタンの文字が読めなくなったのは、これが原因だった。背景色は、1つだけ付ける
- **`strictPort`**：Vite は、5173番が使えないと、黙って別の番号で起動する。`strictPort: true` で、失敗させる。ただし、他のプロセスが全アドレス（`::`）で5173番を握っていると、気づけない。起動前の確認が必要（スキル `dev-port-conflict`）

## 5. やってみよう
1. `docker compose up -d` → `backend/` で `.\gradlew.bat bootRun` → `frontend/` で `npm run dev` の順に起動する
2. http://localhost:5173 を開き、3列にカードが並ぶのを確認する
3. 「キーワード」に「買」と入れて、「検索」を押す → カードが2枚に絞られる
4. 「期限（この日まで）」に日付を入れて検索する → 期限のないカードは、出てこない
5. バックエンドを止めて、画面を開き直す → エラーが表示される
